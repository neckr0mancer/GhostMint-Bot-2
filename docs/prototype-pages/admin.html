Effective lookup

Answers "why is this user's ceiling 0.1?" — a form plus a result ledger that shows the resolved policy and which layer each value came from.

  • Form: platform, platform user ID, chain
  • Result Ledger: max transaction, daily budget, gas ceiling, simulation, confirmations, active preset
  • Each row annotated user override / group / default
  • An owner renders as "Exempt", never as a number

Layout pattern: the Groups tab's form-left / register-1-ledger-right split.

Register 1 · builds against Groups

Mode presets

Four preset cards — Degen, Fast, Cautious, Normie — each editable by an owner.

  • Per card: simulation mode, confirmation count, human verification, gas multiplier, is_default marker
  • Edit form is register 1 — these values change what every user's transaction costs
  • Display names come from mode_presets.display_name. Do not relabel client-side — migration 038 fixed them at the source
  • Exactly one preset can be default; the unique partial index enforces it

Layout pattern: Groups' card-per-record plus register-1 edit form.

Register 1 · builds against Users & ceilings

Owner access

The most dangerous screen in the product. No colour decoration at all.

  • List of owners and root owners with tier pills
  • Grant / revoke form, each action confirming with the exact account named
  • Invariants stated in plain text on the page: the last owner cannot be removed; there is a maximum of 2 root owners; only a root owner can grant or revoke owner

Layout pattern: Users & ceilings' list plus guarded action form.
